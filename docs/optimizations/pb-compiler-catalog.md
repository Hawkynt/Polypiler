## How to read the table

**Class** says what the upstream document operates on, which is stated in the *Operates on* column:

- `agnostic` — a rewrite on typed IR that holds for any source language and any target.
- `target` — tied to a CPU, a calling convention or the layout of machine code; the class cell names which.
- `source` — tied to PowerBASIC or to the semantics of its BASIC runtime.
- `infrastructure` — an analysis, a representation or tooling that other passes consume, not a rewrite.

**Covered by** names a Polypiler optimization only if its page describes the same rewrite and its conditions
include the upstream input. Where the Polypiler page handles only part of the upstream input, or reaches the
result by a different mechanism, the cell reads `partly O####` and states the difference. A merely related
optimization is not named. `—` means no Polypiler page covers the entry.

**To borrow** is filled for `agnostic` entries that are not covered, and only for them. A partly covered
entry is not a candidate: the stated difference is what a revision of the named page would add. Upstream
splits some optimizations over several documents, so a few candidates describe the same rewrite from two
angles; each upstream document keeps its own row.

Upstream identifiers and Polypiler identifiers both read `O####` and are unrelated. The first column is
always upstream; every identifier in *Covered by* is Polypiler's.
