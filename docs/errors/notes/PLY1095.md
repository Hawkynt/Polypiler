## Cause

The C# runner could not pair the call contract with the program: the profile is not one the runner
knows, the export does not exist or names several overloads, a parameter type has no derived image
(`decimal`, `nint`, a class), the supplied signature names another image type or mode than the
declaration, the generated driver does not compile against the declaration, the driver read an input
image it could not decode, or the function under test wrote to standard output, which carries the
driver's answers.

## Example

```text
error PLY1095: the parameter 'table' is u32 in the signature, seq<i32> in the declaration
error PLY1095: call 1: the function under test wrote to standard output
```

## What to do

Make the signature in the vector file name the image types of the declaration, in the same order;
an array whose content after the call belongs to the contract may be declared `inout`. Keep output
of the function under test off standard output.
