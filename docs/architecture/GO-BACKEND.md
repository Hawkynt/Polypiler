# Go backend

**Status:** implemented for the subset below ([#686](https://github.com/Hawkynt/Polypiler/issues/686): [#692](https://github.com/Hawkynt/Polypiler/issues/692), [#689](https://github.com/Hawkynt/Polypiler/issues/689), [#690](https://github.com/Hawkynt/Polypiler/issues/690)); stage 8 of the [pipeline](PIPELINE.md). Related: [backends](BACKENDS.md) · [Go frontend](GO-FRONTEND.md) · [exceptions](../reference/exceptions.md).

`Polypiler.Core.Backends.Go` writes one Go module per IR module: `go.mod`, the package file and
`polyrt.go` with the helpers the package calls. As every backend it builds a syntax tree
(`Syntax/GoSyntax.cs`, shaped after `go/ast`), runs its target passes (`Passes/GoTargetPasses.cs`:
O0501, unused helper removal) and prints the tree (`Printing/GoPrinter.cs`). `GoSyntaxReader` reads
the printed subset back for the parse-back sweep and reads the Go text of the helpers into the tree.

```text
polypiler translate Adler32.cs --from csharp --to go --profile go1.22 --go-module example.test/adler32 --output out
```

## Profiles

`--profile go1.18` to `go1.27`, `go/1` the newest, the language version of the pinned `go` of
`tooling/toolchains.lock`. The version is the `go` directive of `go.mod`, which also selects the
semantics of the language, and the output builds with that version and every later one. `int` and
`uint` are 64 bits wide in every profile; the generated code names them only for what Go's own
functions take and give. `polypiler targets` lists the versions that brought a construct of the
capability table (`Profiles/GoCapabilities.cs`):

| Construct | Since | Before |
| --- | --- | --- |
| type parameters | 1.18 | — |
| `min`, `max` | 1.21 | a helper per type, `plyMinInt32` |
| `slices`, `clear` | 1.21 | a loop |
| `for i := range n` | 1.22 | a three-clause `for` |
| a new loop variable in every pass | 1.22 | a copy in the body |
| `for x := range f` | 1.23 | a callback |

## Layout

gofmt's layout is the printer's own, never a rerun of gofmt: tabs, the label of a statement one
level to the left, `case` at the level of its `switch`, the types of a struct's fields in one column,
the imports sorted, exactly the parentheses precedence needs, and the spaces around a binary operator
chosen by precedence and depth as `go/printer` chooses them - `a*b + c`, `x[i+1]`,
`a << (n & 31)`. Those rules are converted from `go/printer` (BSD-3-Clause,
`Printing/THIRD-PARTY-NOTICE.go.txt`). Every file starts with `// Code generated by polypiler. DO
NOT EDIT.` Names are MixedCaps (`GoNaming`): a public function is exported, everything else is not,
the initialisms of the Go conventions stay in one case (`GetID`, `CRC32Update`), a keyword or
predeclared name gets a trailing `_`; two functions with one Go name are `PLY2172` (Go has no
overloading). An invalid `--go-module` is `PLY2173`.

## Lowering

| IR | Go |
| --- | --- |
| `i8` … `u64`, `f32`, `f64`, `bool`, `str` | `int8` … `uint64`, `float32`, `float64`, `bool`, `string` |
| array | slice `[]T`; `IrNewArray` is `make`, `IrArrayLength` `int32(len(a))` |
| struct | struct type with exported fields; `==` where Go compares as the IR does, a generated `plyEqual<T>` where a float field must let a NaN equal a NaN |
| constant | a typed literal; a constant expression folded with the IR's semantics first, since Go folds exactly and refuses an overflow; NaN, infinities and -0 through `math` |
| `Add` `Sub` `Mul`, bitwise | Go's operator; on a narrow type widened and narrowed back, the operator of the narrow type |
| `Shl` `Shr` `ShrLogical` | the count masked to the IR's width, `a << (n & 31)`; a logical shift of a signed value through its unsigned type |
| signed `Div`/`Rem` | Go's where the divisor is a constant other than 0 and -1, else `plyDivInt32`, which traps on `MinInt / -1` where Go wraps |
| checked arithmetic, negation, conversion | `plyAddCheckedInt32` …, `math/bits` on 64 bits |
| float `+`/`-` of a product | `float64(a*b) + c`: the conversion forbids fusion |
| float to integer | `plyFloatToInt32Sat`, `plyFloatToInt32Checked`: Go leaves an out-of-range conversion to the implementation |
| rotates, counts, reversals | `math/bits` on every width |
| sqrt, abs, roundings, min, max, bit casts | `math`; `f32` through `float64` and back, exact for each |
| other float operations | the portable implementation, as in every backend |
| other integer operations | the helper of the library (`Library/GoLibrary.cs`) |
| conditional, step as a value | statements before the use, the arms in an `if` |
| `IrIf`, loops, `IrSwitch` | `if`/`else if`, the forms of `for` (a counted loop with its counter in the clause), `switch` without `fallthrough` |
| trap, throw | a panic with the text of the trap |

Operands are evaluated in the IR's order: Go fixes the order of calls but not of the reads of an
element, a field or a global around them, nor of statements an operand needs, so an earlier operand
that could see a later one's effect is taken into a temporary first. Nothing is declared that nothing
reads; a function whose end Go cannot see ends in `panic("unreachable")`.

Refused: classes and interfaces, closures, function values, exceptions with handlers, collections,
lazy sequences, async (`PLY2150`, `PLY2151`, `PLY2160`, `PLY2170`).

## Checks

`Polypiler.Tests/Backends/Go`: the emitted forms, the profiles and names, the printer and reader on
texts gofmt leaves unchanged, and every prototype source parsed back. The Go layer
(`tooling/ci/layers/go.yaml`, job `layer-go`) builds, vets and runs every prototype fixture and every
integer operation on every width against the C# compiler's build, the interpreter and the bit-by-bit
reference (`Polypiler.Tests.Acceptance/Go`).
